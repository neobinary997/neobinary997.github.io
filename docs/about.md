# 关于 Neo

我是 Neo，一名关注端到端交付的 Agent 全栈工程师。我希望解决的不只是“代码怎么写”，而是如何把一个业务目标转化为可维护、可验证、可上线并能持续运营的软件系统。

我有零售电商大促和跨境电商 OMS 场景经验，长期关注复杂订单链路、异常处理、系统可靠性与生产协作。现在，我把这些工程经验延伸到 AI Agent：从工具和边界设计，到评测、可观测性、发布与运维。

## 这里写什么

- **工程实践**：记录一个 Agent 从原型进入生产需要补齐的系统能力；
- **架构取舍**：解释方案为什么这样设计、适用边界是什么；
- **案例复盘**：在保护业务信息的前提下，还原复杂系统中的问题、约束与结果；
- **原文解读**：引用可信来源，并补充自己的工程判断和落地清单。

## 内容方向

内容围绕 AI Agent 全生命周期，按五个方向组织：

| 方向 | 关注内容 |
|------|----------|
| Agent 系统构建 | Agent 架构设计、上下文工程、状态管理、工具调用 |
| 工程化处理 | Harness 工程、架构框架、分层设计、安全防护 |
| 可观测性 | 评测体系、监控、trace 分析、日志 |
| 评估体系建设 | 离线/在线评测、基准集、回归测试、质量与成本指标 |
| Ops | 部署运维、CI/CD、灰度发布、SRE 实践 |

## 写作原则

每篇正式文章应尽量包含问题背景、约束、方案、关键实现、取舍和验证结果。未完成内容不会进入文章列表、RSS 或站点地图。
